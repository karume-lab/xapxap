# Xapxap

Welcome to Xapxap! This repository contains a self-hosted Supabase setup using Docker. 

## Project Structure

- `apps/supabase/`: Contains Supabase-specific configurations, migrations, and volumes.
  - `volumes/`: Persisted data for the database, logs, api, etc.
  - `migrations/`: Database initialization scripts and schema migrations.
  - `functions/`: Deno edge functions.
- `docker-compose.yml`: The main Docker Compose configuration that orchestrates the entire Supabase stack.
- `.env`: Environment variables used by `docker-compose.yml` to configure the stack securely.

## Getting Started

### Prerequisites

- [Docker](https://docs.docker.com/get-docker/) installed and running.
- [Docker Compose](https://docs.docker.com/compose/install/) available on your system.

### Running the Stack

To start the Supabase stack, simply run the following command from the root of the project:

```bash
docker compose up -d
```

This will pull the necessary images and start all the services in the background. Note: The first time you run this, it may take a while to download the images and initialize the database.

### Access Points

Once the stack is up and running, you can access the following services on your local machine:

- **Supabase Studio (Dashboard):** [http://localhost:54323](http://localhost:54323)
- **REST API (Kong Gateway):** [http://localhost:54321](http://localhost:54321)
- **Postgres Database:** `postgresql://postgres:<YOUR_POSTGRES_PASSWORD>@localhost:54322/postgres`

## How It Works Under the Hood

The setup heavily relies on the official Supabase Docker orchestration, adapted for local development or self-hosting:

1. **Docker Compose (`docker-compose.yml`)**: This file sits at the root and acts as the master manifest. It defines all the microservices required for Supabase (e.g., Kong API Gateway, GoTrue for Auth, PostgREST for REST APIs, Realtime, Storage, Vector, Studio, etc.).

2. **Environment Variables (`.env`)**: Secrets such as `POSTGRES_PASSWORD`, `JWT_SECRET`, and API keys are stored here. They are injected into the respective containers upon startup.

3. **Volumes & Persistence (`apps/supabase/volumes`)**: All data generated by the services is mapped to local folders within `apps/supabase/volumes`. This includes Postgres data (`db/`), Kong configuration (`api/`), Vector logs (`logs/`), and others. This ensures your data persists across container restarts.

4. **Migrations & Initialization (`apps/supabase/migrations`)**: The initialization SQL files (such as those defining the `_realtime` and `_supabase` schemas) are mapped into the Postgres container's initialization directory (`/docker-entrypoint-initdb.d/migrations/`). When the Postgres container boots up for the first time, it automatically executes these scripts to set up the internal Supabase architecture.

### Stopping the Stack

To gracefully stop the stack without losing your data, run:

```bash
docker compose down
```

If you ever want to completely wipe your setup and start fresh, you can remove the contents of the `apps/supabase/volumes/` directory (WARNING: This will delete all your database and storage data!).
